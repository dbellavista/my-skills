# Where knowledge belongs

| Knowledge | Default home |
| --- | --- |
| Stable project architecture and behavior | Relevant maintained documentation. |
| Short conventions every project agent needs | Project agent instruction file. |
| Reusable task procedure | A focused custom skill, with conditional detail in references. |
| Concrete unfinished improvement | Development backlog with evidence and completion criteria. |
| Delivered behavior | Changelog or existing release history. |
| Decision with alternatives and consequences | Architecture decision record or existing decision log. |
| Durable project-specific fact needed across sessions | Accessible project memory, linked to its source. |
| Personal preference across projects | User memory only when explicitly supported and in scope. |

Follow the project's existing homes rather than creating a parallel system. Memory is an
index and continuity aid, not a second copy of the documentation. Store concise facts
and pointers, retaining date and scope when a fact can become stale. Mark uncertain
conclusions as uncertain and remove outdated summaries when superseded by evidence.

Skills should explain decisions and fragile mechanics the agent would otherwise miss.
Avoid copied manuals, machine-specific paths, accumulated universal prohibitions, and
speculative exceptions. A project-specific procedure can mention its local paths; a
publishable skill must parameterize names and exclude private context.

Before removing or renaming a maintained source, inspect its incoming references and
preserve required history. Prefer correcting a canonical source to adding another warning
in every related file. Update callers when a skill name or supporting resource changes.

Useful review report:

- Coverage: sources actually reviewed and unavailable history or memories.
- Changes: corrected facts, consolidated procedures, improved routing, and validation.
- Open questions: conflicting evidence and specific proposed edits outside writable scope.

Reports should describe actual findings. Do not create an empty template after every pass.
